# Brief schema

Generated by `MODEL_BRIEF` (`claude-opus-5-5`) from aggregates only: the series metrics, cluster and entity recurrence, the format fingerprint, the coverage matrix, the unsupported clusters, and the customer's own-domain context. Raw renders are never sent. Every item carries `evidence_refs`, an array of `{ kind: cluster | entity | reference | page | matrix_cell, id }` that must resolve in the analysis run; a post-check rejects briefs with dangling references.

The zod schema must satisfy the structured-output constraints: no recursion, `additionalProperties: false`, `minItems` of 0 or 1 only, at most 24 optional fields in total; keep fields required where possible.

```ts
Brief = {
  target_query: string,
  locale: { gl: string, hl: string, device: 'desktop' | 'mobile' },
  window: { start: string, end: string, n_renders: number, confidence: 'low' | 'medium' | 'high' },

  answer_lead: {
    text_to_say_first: string,        // one or two sentences that answer the query directly
    max_words: number,                // target length, derived from winners' words-to-answer median
    evidence_refs: EvidenceRef[]
  },

  must_cover_topics: Array<{
    topic: string,
    recurrence: number,               // 0..1, from cluster recurrence
    satisfies_clusters: string[],     // cluster ids
    evidence_refs: EvidenceRef[]
  }>,

  must_mention_entities: Array<{
    entity: string,
    role: 'recommended' | 'cited_domain',
    recurrence: number,
    note: string,                     // e.g. "best-for label the AI Overview uses"
    evidence_refs: EvidenceRef[]
  }>,

  required_formats: Array<{
    kind: 'table' | 'ranked_list' | 'unordered_list' | 'comparison_block' | 'faq' | 'pros_cons',
    spec: string,                     // e.g. suggested columns, number of items
    share_of_renders: number,
    evidence_refs: EvidenceRef[]
  }>,

  evidence_to_include: Array<{        // baseline evidence the winners have
    kind: 'original_data' | 'test_result' | 'screenshot' | 'quote' | 'pricing' | 'spec',
    description: string,
    evidence_refs: EvidenceRef[]
  }>,

  new_to_cite: Array<{                // Jake's step 5: give Google something NEW
    idea: string,
    why_google_lacks_it: string,      // tied to an unsupported cluster, a matrix gap or an unanswered question
    how_to_produce: 'original_data' | 'first_hand_test' | 'updated_statistics' | 'better_comparison' | 'useful_table' | 'unanswered_question' | 'better_examples',
    evidence_refs: EvidenceRef[]
  }>,

  questions_to_answer: Array<{ question: string, evidence_refs: EvidenceRef[] }>,

  outline: Array<{
    heading: string,
    level: 2 | 3,
    purpose: string,
    target_words: number,
    covers_topics: string[]
  }>,

  technical_checklist: string[],      // indexable, snippet-eligible, no nosnippet, text in HTML, JSON-LD types to add, visible author and date
  avoid: string[],                    // claims the AI Overview never includes, bloat, self-promotional "best" framing without third-party support

  ai_generated: true
}
```

## Export

Markdown with YAML front matter:

```
---
ai_generated: true
generated_at: 2026-10-13T09:00:00Z
model_alias: MODEL_BRIEF
prompt_version: brief-v1
human_review_required: true
---
<!-- ai-generated: legiit-overviews brief v1; human review required -->
```

The marker satisfies the EU AI Act Article 50 machine-readable requirement for generated text and travels with every export. v1 exports Markdown only, so the marker cannot be lost in conversion.

## Deterministic post-checks

- Every `must_cover_topics[].satisfies_clusters` id exists and has recurrence at or above 0.40.
- Every `must_mention_entities[].entity` recurs in at least 2 renders.
- No 12-word span of any string in the brief matches a stored competitor quote (`cited_page.quotes`).
- No raw AI Overview block text appears verbatim in the brief (the brief is built from aggregates, so this is a regression guard).
- The outline covers every `must_cover_topics[].topic` at least once.

## Draft score (deterministic, v1)

Given a URL or pasted text, run the page-feature extractor and compute:

- Topic coverage: share of `must_cover_topics` whose topic terms or cluster entities appear.
- Entity coverage: share of `must_mention_entities` present.
- Format compliance: share of `required_formats` present.
- Words to answer: the draft's words-before-first-direct-answer versus the CORE pages' median (full marks at or below the median).
- Numeric density versus the CORE median.
- Eligibility: indexable, no `nosnippet` or restrictive `max-snippet`, text present in HTML, author and date visible.

Composite 0 to 100 with fixed weights (coverage 30, entities 20, formats 20, answer position 15, evidence density 5, eligibility 10) and a prioritised fix list. Repeated runs on the same input are identical. The LLM rubric for new-to-cite fulfilment is v1.1.
